# Web Research
## Purpose
Acquire implementation-relevant domain knowledge before building unfamiliar systems.
## Source order
1. Official product/docs/developer portal
2. Official repositories/release notes
3. Standards/specifications
4. Maintainer discussions
5. Reputable technical sources
6. Community reports for real-world caveats
## Method
- Identify versions, dates and platform constraints.
- Compare official and non-official claims; flag conflicts.
- Prefer current primary sources for normative behavior.
- Search for known limitations, deprecated APIs, security constraints and common failure modes.
- Record only facts that affect architecture, UX, implementation or testing.
## Output
Return: facts, source/authority, version caveats, contradictions, implementation consequences, unresolved questions.
## Failure handling
If documentation conflicts, do not silently choose. Explain the conflict and verify version/context.
