# Component Research
## Purpose
Reuse mature, accessible primitives before hand-building complex commodity UI.
## Search order
1. Existing project components/design system
2. shadcn/ui for application UI
3. Radix UI or React Aria primitives
4. Approved registries/libraries
5. Aceternity-style components for justified marketing visuals
## Evaluate
Accessibility, dependency cost, bundle impact, maintenance, mobile behavior, customization, license, framework/version compatibility and fit with `DESIGN.md`.
## Rules
Do not install a package because a demo looks impressive. Prefer the simplest maintainable solution. Adapt imported components to project tokens instead of introducing a second visual language.
