# AI Web Rules

- Do not start medium/large website implementation before requirements, IA and visual direction are sufficiently defined.
- Research unfamiliar domains using current primary sources; compare conflicting sources and versions.
- References are for extracting principles, not cloning brand identity.
- Do not assume modern = gradient, AI = purple, premium = black/gold, dashboard = four KPI cards, minimal = empty space everywhere.
- Avoid unjustified glassmorphism, giant rounded cards, excessive glow/shadow, floating blobs, random animation, oversized hero text, icon-per-sentence and card-per-section layouts.
- Every visual choice should support hierarchy, brand, content, interaction or usability. Remove decoration without purpose.
- Reuse the project's design system and components.
- Render and visually inspect major UI work before declaring it complete.
- After repeated failure, stop repeating the same patch. Re-check assumptions, user requirements, environment, architecture, dependencies, data contracts and documentation.
- Prefer concise implementation notes and load only relevant skills to reduce context/token usage.
