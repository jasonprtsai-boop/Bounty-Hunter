## 最具競爭力題目方向

### 1. 智慧宮廟 AI 服務入口

概念：用 LINE MINI App / LIFF + Chatbot 做宮廟導覽、祭典問答、參拜流程、活動報名、點燈/安太歲/祈福服務查詢、信眾通知、現場人流或排隊引導。

競爭力：

- 符合特獎「智慧宮廟」且可重複獲獎。
- 主辦協辦單位包含台中萬春宮，題目貼合度高。
- 可同時包住智慧零售、智慧照護、智慧觀光、在地文化。
- Demo 容易：掃 QR / LINE Touch / Rich Menu 開 MINI App，Chatbot 問答，後台模擬活動報名與通知。

風險：

- 宗教內容要尊重，不應讓 AI 扮演神明或斷言命運。
- 需要明確區分服務資訊、文化導覽、行政流程。

### 2. 校園 AI 生活助理

概念：學生透過 LINE 問課程、校務、獎學金、場地借用、活動、社團、失物招領；LIFF / MINI App 提供個人化任務、地圖、表單與通知。

競爭力：

- 參賽者本身就是目標族群，痛點容易驗證。
- 高度符合智慧校園。
- 可用 RAG 做校務 FAQ，Demo 清楚。
- B2B2C 商業模式可賣給學校或系所。

風險：

- 若只做 FAQ Bot 會太普通，需加入流程型服務，例如場地預約、校園活動配對、個人化提醒。

### 3. 智慧零售 AI 店員 + MINI App 下單

概念：小店或夜市攤透過 LINE OA 接客，AI 推薦商品、查庫存、收集需求；MINI App 下單、預約取貨、會員點數；Rich Menu 固定入口。

競爭力：

- 市場需求大，商業模式清楚。
- LINE 生態結合自然：OA 導流、Chatbot 問答、LIFF / MINI App 下單、Messaging API 通知。
- Demo 可在 3 分鐘內呈現完整購物流程。

風險：

- 競品多，必須選一個有特色的垂直場景，如校園商圈、宮廟周邊攤商、長照用品、活動攤位。

### 4. 智慧照護 家屬協作助理

概念：照護者透過 LINE 記錄服藥、回診、餐食、跌倒風險、日常狀態；AI 幫忙摘要與提醒；家屬群收到必要通知。

競爭力：

- 社會需求強，能展示 AI 的實用價值。
- LINE 是家庭溝通場景，採用門檻低。
- 可結合語音、圖片辨識、排程、提醒。

風險：

- 醫療與個資敏感，不能做診斷。應定位為「照護記錄、提醒、資訊整理」。

### 5. 宮廟祭典人流與攤商智慧服務

概念：大型祭典時，用 LINE MINI App 進行路線導覽、擁擠度回報、排隊預估、攤商地圖、集章、遺失物與緊急通報。

競爭力：

- 智慧宮廟加智慧零售，創造力高。
- 場景鮮明，評審容易想像落地。
- 可加入 LINE Touch / Beacon / QR 作為現場入口。

風險：

- 若做即時人流需要資料來源。Demo 可先用模擬資料，商用版再接 IoT / 人流計數。

## LINE 開發軟體與平台地圖

### LINE Developers Console

用途：管理 Developer、Provider、Channel，建立 LINE Login / LINE MINI App / Blockchain Service 等 Channel；Messaging API Channel 則需透過建立 LINE 官方帳號並啟用 Messaging API 產生。

競賽用途：所有作品都需要它來建立 Provider、Channel、LIFF / MINI App、Webhook、Channel access token。

### LINE Official Account / OA Manager

用途：官方帳號營運後台，可管理基本資料、權限、回應設定、自動回覆、Webhook、Messaging API、Rich Menu、帳務等。

競賽用途：作品入口、客服/服務對話、Rich Menu、加入好友、分眾經營。

### Messaging API / Chatbot

用途：讓 Bot Server 透過 Webhook 接收使用者事件，再用 reply / push / multicast / narrowcast / broadcast 等方式傳訊息。

可做：AI 客服、RAG 問答、通知、Flex Message 卡片、Quick Reply、Rich Menu、使用者資料與互動流程。

官方 SDK：Java、PHP、Python、Node.js、Go、Ruby。

### LIFF

用途：LINE Front-end Framework，讓 Web App 在 LINE 內開啟並取得 LINE 平台能力，例如登入、使用者資料、分享、QR 掃描、關閉視窗、加入桌面捷徑等。

工具：

- LIFF SDK
- LIFF CLI
- Create LIFF App
- LIFF Playground
- LIFF Inspector
- LIFF Server API

競賽用途：做表單、地圖、個人化頁面、互動工具、付款/預約/排隊等比純聊天更完整的體驗。

注意：官方已建議新的 LIFF app 優先以 LINE MINI App 形式建立，因為 LIFF 未來會整合到 LINE MINI App 品牌。

### LINE MINI App

用途：在 LINE App 內提供接近原生 App 的網頁服務，不需額外安裝 App。台灣已有 MINI App，分為未驗證與已驗證；已驗證 MINI App 可有更完整入口與服務訊息能力。

可做：點餐、預約、會員卡、排隊、活動報名、票券、照護服務、校園服務。

工具：

- LINE MINI App Channel
- LINE MINI App Playground
- LIFF API
- Service Message API
- MINI App UI components
- MINI App demo / quickstart / review guidelines

競賽用途：最適合拿來展示完整產品，而不只是 Bot。

### LINE Login

用途：以 LINE 帳號登入網站、Web App、iOS / Android App、Unity game；基於 OAuth 2.0 / OpenID Connect。

競賽用途：會員識別、個人化服務、綁定校園/零售/照護帳戶。

### Rich Menu / Flex Message / Quick Reply

用途：改善 LINE OA 互動體驗。Rich Menu 是聊天頁底部大型選單；Flex Message 可做漂亮的卡片、列表、票券、商品、行程；Quick Reply 適合流程式選項。

競賽用途：提高 Demo 質感，很容易讓評審感覺「這真的能上線」。

### LINE Beacon

用途：BLE Beacon 進入範圍時觸發 Bot webhook event。LINE Beacon 可用於日本、台灣、泰國。需要 LINE Beacon 相容裝置或符合 LINE Simple Beacon 規格的 BLE 裝置。

競賽用途：智慧宮廟、智慧零售、展場、校園導覽、到店任務。

限制：Beacon banner 等部分功能限企業申請；使用者也需開啟 Bluetooth 與 LINE Beacon 設定。

### LINE Touch

用途：台灣 LINE Biz-Solutions 的 NFC 現場入口。使用者用支援 NFC 的手機碰觸感應標籤，可加入官方帳號、領券、集點、開啟 LINE MINI App 等。

競賽用途：智慧宮廟、智慧零售、校園活動報到，非常適合做 OMO 入口概念。

限制：目前屬企業導入/申請型產品；比賽 Demo 可用 NFC tag 或 QR 先模擬。

### LINE Pay

用途：線上付款 API，可處理付款請求、確認、退款、預授權等。

競賽用途：智慧零售、宮廟捐款/服務費、活動報名付款。

限制：競賽 Demo 可先模擬付款，不一定要真的串金流。

### LINE Social Plugins / URL Scheme

用途：網站加入 LINE 分享、加好友、Like 等按鈕；URL Scheme 可開 LINE 功能、開 LIFF / MINI App、分享文字。

競賽用途：導流、分享、活動邀請、好友推薦。

注意：`line://` scheme 已 deprecated，應使用 `https://line.me/R/`、`https://liff.line.me/`、`https://miniapp.line.me/`。

### LINE Ads API / LINE Conversion API

用途：廣告投放管理、轉換事件回傳、成效衡量。

競賽用途：若企劃強調商業化，可放在未來擴充，不一定要在原型中實作。

### Mini Dapp

用途：LINE Web3 / blockchain 相關服務入口。可做鏈上資產、獎勵、遊戲化等。

競賽用途：除非題目確實需要數位資產或忠誠點數，否則不建議當主軸，會讓產品焦點變散。

### LINE Codelabs

用途：官方教學專區，包含 Chatbot、GenAI Bot、LINE Beacon、Rich Menu、LINE MINI App、Service Messages、n8n/Gemini 等實作教學。

競賽用途：快速學習與原型參考。

### LINE Design System

用途：LINE 官方設計系統，提供 LINE 產品設計原則、UX Guidelines、Foundation、Typography、Color、Layout、Iconography、Object Styles、LINE Voice、案例等設計資源。

競賽用途：不是 API 或 SDK，但很適合用來提升作品的 UI / UX、文案語氣、元件一致性與簡報說服力。特別是做 LIFF / LINE MINI App / Rich Menu / Flex Message 時，可參考其「Clear primary tasks」「Chat comes first」「Reliable design」「Cohesive experience」等原則，讓作品更像真正能放進 LINE 生態的服務。

注意：若要做 LINE MINI App，仍要同時參考 LINE MINI App 官方 UI components、safe area、icon、review guidelines 等開發文件；LINE Design System 是上位設計語言與體驗準則，不取代產品個別規範。

## 已停用或不建議使用

### LINE Notify

LINE Notify 已於 2025-03-31 停止服務。通知類需求應改用 Messaging API 或 MINI App Service Messages。

### LINE Things

LINE Things Developer Trial 已於 2024-03-31 停止提供，相關文件與 API reference 也已於 2024-05-13 停止提供。歷史上可用於 BLE IoT，但新作品不建議依賴。

歷史硬體參考：

- LINE Things dev board
- ESP32-DevKitC
- M5Stack
- M5StickC
- Adafruit Feather nRF52 Bluefruit LE
- Adafruit Feather nRF52840 Express
- BBC micro:bit
- Obniz
- Puck.js

若要做硬體互動，現階段較建議使用 LINE Beacon、LINE Touch / NFC 或 QR code 作入口，再把資料送到自己的後端與 LINE Bot / MINI App 串接。

## 推薦技術組合

最穩的競賽原型架構：

- LINE Official Account 作主入口
- Rich Menu 放 3-4 個核心功能
- Messaging API + AI 後端做 Chatbot
- LIFF / LINE MINI App 做需要表單、地圖、清單、儀表板的頁面
- Flex Message 展示結果
- Service Message / push message 做通知
- QR / NFC / Beacon 做現場入口

建議後端：

- Node.js / Express 或 Python / FastAPI
- OpenAI / Gemini / Claude 任一 LLM API
- RAG：學校/商家/宮廟/照護資料庫
- Database：SQLite / PostgreSQL / Firebase / Supabase
- 部署：Render / Railway / Vercel / Cloud Run

## 目前首選題目

若以得獎機率和創意平衡來看，首選是：

智慧宮廟 AI 服務入口 + 祭典/信眾/攤商/照護整合

原因：

- 直接命中特別獎。
- 題目不像一般校園 FAQ 或商店 Bot 那麼容易撞題。
- 可以同時展示 AI、LINE MINI App、Chatbot、Rich Menu、通知、OMO 入口。
- 有明確在地場景與商業模式：宮廟、周邊商圈、活動服務、會員/信眾經營。
- Demo 可以在 3 分鐘內做得很完整。

最小可行 Demo：

1. 使用者掃 QR / NFC 開啟 LINE OA。
2. Rich Menu 選「參拜導覽」「活動報名」「AI 問事務」。
3. AI Chatbot 回答宮廟歷史、參拜流程、活動時間。
4. MINI App 顯示祭典地圖、排隊狀態、攤商優惠、服務預約。
5. 使用者完成報名後收到 LINE 通知。
6. 後台儀表板顯示報名、熱門問題、攤商點擊、現場回饋。

備選題目：

- 校園 AI 行政生活助理
- 智慧零售 AI 店員 + MINI App 下單
- 家屬協作智慧照護助理
- 宮廟祭典人流與攤商智慧服務
